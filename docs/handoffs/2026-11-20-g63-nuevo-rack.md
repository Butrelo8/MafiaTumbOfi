## Gotchas
Findings destination (repo CLAUDE.md): general method -> visual-lab (listed here as `gotchas:` lines for the report); site notes -> this repo's `docs/` (done: `docs/g63-nuevo-dueno.md`, `docs/design/references.md`).
- gotchas: `Mesh.transform` on shared mesh data compounds once per user (44 fringe strands flew to x 75) -> make the data single-user before baking world matrices.
- gotchas: `Object.bound_box` is stale after `Mesh.transform` until a depsgraph update (wheel centres came out at y 22) -> take bounds from the vertices.
- gotchas: re-importing the same glb names its materials `pp_fleco.001`, and three.js sanitises that to `pp_fleco001`, so the page's exact-name regex missed them -> relink each kept slot to the un-suffixed material.
- gotchas: glTF-Transform `mergeDocuments` leaves two buffers (GLB write fails: "must have 0-1 buffers") -> run `unpartition()` after it; a leftover KHR_draco extension needs the encoder or `ext.dispose()` before a plain write.
- gotchas: the glTF importer leaves quaternion rotation mode, so `rotation_euler` is ignored -> set `rotation_mode = "XYZ"` first.
- gotchas: `node.exe` only sees env names listed in `WSLENV`, so `VISTAS` / `ANCHOS` ran all 44 shots until added (`WSLENV=PW:CHROME:VISTAS:ANCHOS`).
- gotchas: putting a roof load into the truck box that vivoRuta orbits failed 30 of 125 tests (exit paths cross the box) -> the box is the body only, as for the 6x6.
- gotchas: a hook blocks any Bash line containing `python3` and `numpy`, even in an edit script -> use the Edit tool for those changes.
- gotchas: Blender glTF import of the baked cast clip gives different poses than the exporter's own evaluation for 3 of 4 rigs (see Open) -> build placement files from the owner's pose dump, not from the glb.
